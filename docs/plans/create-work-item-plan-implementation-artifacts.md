## 1. Objective

Create a reusable generic plan-bound implementation package: three named agent definitions, one implementation skill, an execution-ledger template, and an implementation-handoff template. The package enforces its implementation-readiness gate when a future caller supplies a work-item plan.

## 2. Source Extraction and Traceability

### Source material

- [Recommended Artifacts for Implementing Work-Item Plans](../research/work-item-plan-implementation-artifacts.md) / "Executive Summary" and "Recommendation": create the plan-bound package only when a first low-risk work-item plan provides real targets, commands, environment boundaries, and acceptance evidence; the work-item plan remains the authority for objective, scope, tasks, validation, and stop conditions.
- [Recommended Artifacts for Implementing Work-Item Plans](../research/work-item-plan-implementation-artifacts.md) / "Recommended Artifact Set": the package contains exactly an implementation orchestrator, an editable implementer, a read-only implementation reviewer, an implementation skill, an execution-ledger template, and an evidence-handoff template. The initial orchestrator delegate allowlist contains only the implementer and reviewer.
- [Recommended Artifacts for Implementing Work-Item Plans](../research/work-item-plan-implementation-artifacts.md) / "Implementation-Readiness Gate": before implementation, the physical plan must provide an objective, traceability, scope, targets or bounded discovery, ordered tasks, checks with working directories and expected results, evidence location, external boundaries, and plan-step coverage; missing controls produce a blocker report.
- [Qualities and Best Practices for Work-Item Plan Implementer Artifacts](../research/implementer-artifact-qualities-and-best-practices.md) / "Quality Model" and "Best Practices": the orchestrator owns plan-step coverage, sequencing, integration, final validation, and handoff; specialist delegation is plan-directed; evidence records changed paths, commands, results, and limitations; a reviewer reports findings without editing or accepting.
- [work-item-plan orchestrator](../../.github/agents/work-item-plan-orchestrator.agent.md), [work-item planner](../../.github/agents/work-item-planner.agent.md), and [work-item plan reviewer](../../.github/agents/work-item-plan-reviewer.agent.md): the established repository role convention is a user-invocable, read/search/agent coordinator; a non-user-invocable, read/search/edit worker; and a non-user-invocable, read/search reviewer.
- [work-item plan-authoring skill](../../.github/skills/work-item-plan-authoring/SKILL.md) and [work-item plan conventions](../../.github/instructions/work-item-plans.instructions.md): a physical work-item plan is the repository-local execution recipe and authority; it must retain targets, ordered tasks, checks, evidence, and stop conditions.

## 9. Stop Conditions and Escalation

Stop and use the blocker report when:

- No plan under `docs/plans/` has a bounded repository-local scope that demonstrates low risk and fully passes the applicable readiness criteria, or a candidate requires the executor to infer a material target, architecture, value, validation command, expected result, evidence location, or approval boundary.
- A target conflicts with an existing artifact, the local agent schema cannot express the required least-privilege contract, or the source/repository conventions conflict materially.
- A required check is unavailable, fails, or returns an unexpected result; a template or agent contract expands authority beyond the passed plan; or terminal capability cannot be tied to a candidate-plan command.
- Work would require a secret, personal data, external-system mutation, deployment, production action, an MCP configuration, or any excluded artifact.
- Evidence cannot be retained at a location verified by the candidate plan or existing repository-local context, or a task would require creating a new durable evidence store.
- A task would modify the candidate plan, existing artifacts, implementation sources, or any path outside the six target-map artifacts.

Blocker report: `step`, `observed fact`, `command/output or path`, `impact`, `decision or input needed`, and `safe next action`.
